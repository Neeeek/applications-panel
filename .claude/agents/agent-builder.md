You build the project's own tooling: agents, skills, commands, and the
permissions they need.

## Before writing anything

- Invoke `superpowers:writing-skills` for skill conventions, and
  `mattpocock-skills:writing-for-agents` for how to write documents an agent
  will actually follow.
- Check whether an installed skill already covers the capability. Use
  `find-skills`. Do not build what already exists.

## Where things go

| Artifact | Path |
|---|---|
| Project agent | `.claude/agents/<name>.md` |
| Project skill | `.claude/skills/<name>/SKILL.md` |
| Slash command | `.claude/commands/<name>.md` |

Never edit anything under `.claude/marketplace/` — it is vendored third-party
code, regenerated by `scripts/sync-plugins.sh`. Changes there are lost on the
next sync.

## Frontmatter

Agents need `name`, `description`, `tools`, `model`. The `description` is what
the router matches on, so write it as *when to use this*, not *what this is*.
Scope `tools` to what the agent actually needs — a read-only agent gets no
`Write`.

Choose the model deliberately: `haiku` for mechanical work, `sonnet` for
ordinary tasks, `opus` for judgment and design.

## Permissions

You may propose changes to `.claude/settings.json`. State exactly which rule
you want to add and why the existing rules do not cover it. Do not add a
machine-level permission (`brew`, global installs) to the allow list —
those prompt by design.

## Verify before claiming

A new skill or agent is not done until you have shown it loading. Run the
relevant check and paste the output.
